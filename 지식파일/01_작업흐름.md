# 01. 작업 흐름

글 한 편이든 여러 편이든 같은 순서로 진행한다. 글의 내용·말투·구성·그림 스타일은 이 파일이 정하지 않는다.
모두 **내_블로그_설정.md** 에서 사용자가 정한 대로 따르고, 정해지지 않은 것은 그 단계에서 사용자에게 묻는다.

**[확인]** 표시는 사용자에게 묻고 답을 기다리는 곳이다.

| 단계 | 하는 일 | 결과물 | 참고 |
|---|---|---|---|
| 0 | 설정 읽기, 요청 종류 판단 | – | 내_블로그_설정.md |
| 1 | 주제 후보 찾기 | 후보 표 **[확인]** | 08_틀.md |
| 2 | 자료 조사 | 출처 목록, 기존 글과 다른 점 | – |
| 3 | 개요 | 소제목 목록 **[확인]** (설정에서 끌 수 있음) | – |
| 4 | 원고 | 원고(.md) | 02_원고_서식.md, 설정 |
| 5 | 사실 검증 → 고치기 | 검증표 **[확인]**, 고친 원고 | 03_사실검증.md |
| 6 | 윤문 (설정에서 켰을 때) | 다듬은 원고 | 04_윤문.md |
| 7 | 그림 (설정의 방식대로) | 그림 파일 또는 그림 만들 문구 **[확인]** | 05_그림.md |
| 8 | 태그 | 태그 목록 + 확인 방법 | 06_태그.md |

| 10 | 기록 | 진행표 한 줄 | 08_틀.md |

## 0. 시작

- 설정 파일의 칸이 비어 있으면 지침의 '처음 설정'대로 묻고 채운 설정 파일을 만들어 준다.
- 요청 종류: 여러 편 / 후보만 / 주제가 정해진 한 편 / 이미 쓴 글 고치기 / 그림만 / 태그만 / 내가 고친 글 반영.
- 여러 편을 한 대화에서 모두 쓰면 대화가 길어져 앞 내용을 잊기 쉽다. **후보 고르기까지 한 대화, 그다음은 한 편에 한 대화**를 권한다.

## 1. 주제 후보 찾기

- 설정의 블로그 주제·독자·카테고리·빼는 주제 안에서 찾는다. 사용자가 분야를 말하면 그 분야만.
- 후보마다: 제목안 · 한 줄 요약 · 왜 지금(날짜가 있으면) · 근거 출처 주소 · 추천도.
- 이미 쓴 글(설정 파일 '이미 쓴 글')과 겹치지 않게.
- 같은 주제를 검색했을 때 나오는 기존 글을 몇 개 보고, **기존 글이 놓친 것**을 한 줄씩 적는다.
- **[확인]** 어떤 후보로 쓸지, 카테고리는 무엇으로 할지. 추천 하나를 표시하고 기다린다.

## 2. 자료 조사

- 1차 자료(공식 기관·원저자·원문)를 우선한다. 2차 자료(기사·블로그)는 1차 자료를 찾는 단서로만.
- 자료끼리 숫자가 다르면 가장 원본에 가까운 자료로 정하고, 못 정하면 그 숫자는 쓰지 않는다.
- 결과를 짧게 보여 준다: 확정 사실(출처 주소와 함께) / 아직 못 찾은 것 / 기존 글과 다른 점 / 이 글이 답할 질문 한 줄.

## 3. 개요

- 설정의 '글 종류'에 구성이 정해져 있으면 그 구성대로. 없으면 소제목 목록을 제안한다.
- **[확인]** 설정에서 '개요 확인: 안 함'이면 건너뛴다.

## 4. 원고

- 형식은 02_원고_서식.md 의 문법만 쓴다(붙여넣기 화면을 만들기 위해).
- 말투·서두·마무리·제목 형식·고정 문구·구성은 설정 파일을 따른다. 설정에 없으면 담백하고 읽기 쉬운 문체로 쓰고, 끝에 "말투를 정하시면 다음 글부터 맞춥니다"라고 한 줄 알린다.
- 그림이 들어갈 자리에는 `![설명](images/파일이름.png)` 를 넣는다(설정의 그림 방식이 '없음'이면 넣지 않는다).
- 원고 뒤에 '확신 못 한 것' 목록을 따로 적는다 → 5단계 검증에 넘긴다.

## 5. 사실 검증 → 고치기

03_사실검증.md 그대로. 검증표를 먼저 보여 주고, 반영한 원고를 준다.
설정의 고정 문구와 부딪히는 지적은 반영하지 않고 이유를 적는다. 붙여넣기 전 조건: **[확인 필요] 0건**.

## 6. 윤문

설정에서 '윤문: 함'일 때만. 04_윤문.md.

## 7. 그림

05_그림.md. 설정의 그림 방식(없음 / 내 사진 / AI 이미지 생성 / 그래프 / 내 템플릿)대로.
새 스타일을 처음 쓸 때는 **[확인]**.

## 8. 태그

06_태그.md. 후보를 주고 사용자가 확인하는 방법을 안내한다. 원고 마지막 줄에 `#태그 #태그 …`.

## 9. 붙여넣기 화면

**[확인]** 최종 원고를 보여 주고 "이대로 붙여넣기 화면을 만들까요?" → 07_네이버_옮기기.md 대로 원고_변환.py 실행 → .html 내려받기 링크.

## 10. 기록

08_틀.md 의 진행표 형식으로 한 줄을 준다. 사용자가 설정 파일 '이미 쓴 글'에 붙여 두면 다음 후보 찾기에서 겹치지 않는다.

## 이미 쓴 글을 고칠 때

- 요청한 곳만 고친다. 사용자가 "그대로 두라"고 한 곳은 다시 손대지 않는다.
- **사용자가 블로그 에디터에서 직접 고친 글을 붙여 주면**: 원고와 비교해 바뀐 점을 3~6개 규칙으로 뽑아 보여 주고,
  설정 파일 '내가 고친 글에서 배운 규칙' 칸에 붙일 문장으로 정리해 준다. 다음 글부터 그 규칙을 따른다.
