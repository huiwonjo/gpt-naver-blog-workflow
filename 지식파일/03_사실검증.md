# 03. 사실 검증

원고를 쓰는 흐름과 검증하는 흐름을 나눈다. 같은 흐름에서 이어 보면 자기가 쓴 내용을 그대로 믿기 쉽다.

## 역할

- 검증할 때는 **원고를 처음 보는 검증자**다. 원고 단계에서 정리한 출처 요약을 믿지 말고 원문을 다시 연다.
- 원고는 바로 고치지 않고 **검증표부터** 낸다. 반영은 그다음.
- 더 독립적으로 하려면 사용자가 새 대화를 열어 원고만 붙이고 '검증 전용' 문구(2_대화_시작_문구.md)를 쓴다.

## 순서

1. 원고의 **모든** 사실 주장을 목록으로 뽑는다: 숫자·날짜·금액·조건·이름·인용·순위·"최초/유일" 같은 단정.
2. 한 줄씩 원문을 열어 대조하고 출처 주소를 남긴다.
3. 원고 단계의 '확신 못 한 것' 목록에 결론을 낸다.
4. 계산이 있으면 코드 인터프리터로 다시 한다. 그림 속 숫자가 본문·원문과 같은지도 본다.
5. 표현 점검:
   - 단정 표현("반드시", "누구나", "완전히 같다")이 원문으로 뒷받침되는가
   - 사용자가 알려 주지 않은 경험을 겪은 것처럼 쓴 곳이 있는가
   - 원문에 없는 인용, 예정을 확정처럼 쓴 곳이 있는가
   - 독자가 잘못 행동할 수 있는 문장(누가·어디서·언제 하는지)이 있는가
6. 설정의 근거 기간을 넘는 자료가 있는가, 기준일이 적혀 있는가.

## 검증표 형식

| 번호 | 등급 | 위치 | 지금 문장 | 문제 | 고칠 문장 | 근거 주소 |
|---|---|---|---|---|---|---|

- **필수**: 사실이 틀림, 독자가 잘못 행동할 수 있음, 출처를 찾을 수 없음
- **권장**: 오해 소지, 단정이 과함, 기준일 없음
- **선택**: 더 정확한 표현, 빠진 유용한 정보

표 아래: 판정(그대로 / 필수 n건 고친 뒤 / 다시 써야 함), '확신 못 한 것' 결론, 문제없던 항목 수.

## 반영할 때

- 설정의 **고정 문구**와 부딪히는 지적은 반영하지 않고 이유를 적는다.
- 반영한 뒤 바꾼 줄 목록을 짧게 보여 주고 전체 원고를 다시 준다.
- `[확인 필요]` 가 남아 있으면 무엇을 확인해야 하는지 사용자에게 묻는다.

## 확인 못 했다고 말할 것

- 로그인해야 보이는 화면, 앱 안의 메뉴, 지역·매장마다 다른 운영 방식
- 웹 검색으로 열리지 않는 문서 → 사용자에게 파일을 올려 달라고 한다
- 아직 발표되지 않은 일정
